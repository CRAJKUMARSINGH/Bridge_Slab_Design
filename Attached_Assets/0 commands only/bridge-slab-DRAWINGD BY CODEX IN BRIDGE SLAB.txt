SECTION A — WHAT THE APP PRESENTLY SHOWS (CURRENT CAPABILITIES)
============================================================

1) Live SVG / browser drawings (available now)
- GAD (general arrangement drawing)
- Pier elevation / details
- Type-1 abutment section / details
- Deck slab cross-section
- Hydraulic profile and scour diagram
- Pier stability free-body diagram
- Abutment earth-pressure diagram
- Slab reinforcement plan
- Reinforcement detail SVGs + bar schedule for:
  - Pier
  - Type-1 abutment
  - C1 cantilever abutment
- Reinforcement section SVG for pier / abutment

2) DXF / AutoCAD output (available now)
- One downloadable DXF drawing set from endpoint: /api/design/dxf
- DXF engine includes: bridge elevation, plan view, typical cross-section,
  HFL/bed/foundation/scour levels, dimensions, hatching, title block, layers,
  and AC1018/AC1021 compatibility.

3) PDF / report annexure drawings (available now)
- Comprehensive PDF includes annexure sketches:
  - Hydraulic scour profile
  - Pier stability free-body
  - Abutment pressure diagram
  - Slab reinforcement plan

4) Important limitations (NOT implemented yet, per app notes)
- Foundation plan
- Wing wall / return wall drawings
- Cross-section at every pier
- Longitudinal section with soil strata
- Native DWG output
- Separate AutoCAD DXF drawings for individual pier / abutment (current outputs
  are SVG-only or reference assets, not full CAD outputs yet)

NOTE (INTENT):
Certain better features might have been missed during earlier merges.
It is better to incorporate missing better features and neglect inferior ones.

============================================================

Consolidate two app versions into one production-ready version without losing
important functionality. Use Cursor as merge workspace and Replit as a feature
reference.

- cursor-baseline: snapshot before merge work

Merge rules:
- Keep ONE source of truth per concern (auth, data model, report engine, exports).
- Prefer Cursor architecture; port only proven features from Replit.
- Merge module-by-module (avoid one massive merge).
- Validate each merged module before the next one.

Merge sequence:
1) Data models and schema
2) Backend services and business rules
3) API contracts and payload compatibility
4) Authentication and authorization
5) UI screens and components
6) Styling and UX cleanup
7) Reports, exports, and background utilities
