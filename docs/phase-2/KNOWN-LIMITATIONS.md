# KNOWN LIMITATIONS

Things a licensed engineer could reasonably assume this tool does — and it does not.
Written in plain language on purpose. Every row is grounded in evidence in the repo
on 2026-10-30; nothing here is a guess about intent, only a statement of observed
behaviour. Severity is the W01 author's assessment, not a sign-off.

| ID | Limitation | Affects | Severity | Workaround | Target | Owner |
|---|---|---|---|---|---|---|
| KL-01 | **There is no login.** Any caller who can reach the API can run a design and read other projects' results. No accounts, no roles, no per-user separation. | Whole API (`server/app-factory.ts`) | High | Run only on a private network / behind an external proxy until W04 | W04 | W04 |
| KL-02 | **No output is a design.** Every artefact is a DRAFT until a licensed engineer records Name / Date / Registration No. The tool computes and cites; it does not certify. | All deliverables | High | Treat every report as a calculation aid, not a signed design | standing | project owner |
| KL-03 | **Clause citations are not enforced.** There is no clause registry, and `scripts/gates/verify-clauses.mjs` is a NOT-IMPLEMENTED stub. A code shown against a check is not guaranteed to match the clause text of IRC/IS. | Design module, reports | High | Verify each cited clause by hand against the code book | W03 | W03 |
| KL-04 | **The test baseline is not green.** `foundation/manifest.json` records 11 failing tests: kherwara golden (3), `pbt-stats` (4), `ircSlabCalc` (2), `tamper-goes-red` (1), `engineConsistency` (1). A "tests ran" message does not mean they passed. | Test depth | High | Read the failure list in `baselineTestCountProvenance`; do not trust a green summary | W03 | W03 |
| KL-05 | **The two upload limits disagree.** The advertised ceiling is 10 MB (`MAX_UPLOAD_XLSX_BYTES`), but `express.json({limit:'200kb'})` runs first, so a body over ~200 kB is rejected before the 10 MB check ever sees it. One of the two is wrong. | Excel upload | High | Keep uploads under 200 kB until W04 reconciles the limits | W04 | W04 |
| KL-06 | **No roles or permissions.** There is no RBAC; every caller has the same access. | Whole API | High | Isolate deployment | W04 | W04 |
| KL-07 | **No backup and no restore procedure is recorded, and database migrations are not established.** Losing the database is unrecoverable by a documented path. A local JSON fallback (`data/projects-local.json`) exists only when `DATABASE_URL` is unset. | Durability | High | Take manual DB dumps; do not rely on an automated backup | W05 | W05 |
| KL-08 | **There is no job queue.** A run cannot be paused, resumed or cancelled, and a run interrupted by restart or timeout must be issued again from the start. | Compute | Medium | Re-issue the run | W06 | W06 |
| KL-09 | **No compute budget guard.** A heavy input can consume the entire 60 s serverless budget (`vercel.json` `maxDuration`); nothing warns or stops it first. | Compute | Medium | Keep models within the reference sizes | W06 | W06 |
| KL-10 | **The Docker batch image is not built.** `Dockerfile` says "NOT BUILT YET"; there is no verified container image. Batch runs are only exercised locally via `pnpm run pipeline`. | Deployment | Medium | Use the local CLI or the Vercel path | W06 | W06 |
| KL-11 | **Architecture rules are declared but not enforced at lint time.** The `no-restricted-imports` rule for `lib/engine/**` lives in `eslint.config.js`, but the linter's packages are not installed, so the rule is inert. Enforcement today is only via `scripts/foundation/import-guard.mjs`. | Architecture | Medium | Rely on the import guard, not on lint | W02 | W02 |
| KL-12 | **Some TypeScript safety flags are off.** `strictFunctionTypes`, `noImplicitOverride` and `noUnusedLocals` are false, so some type and dead-code errors pass the compiler. | Codebase | Medium | Review by eye | later | later |
| KL-13 | **The `xlsx` library is abandoned** (`SECURITY-AUDIT-2026-10-12.md`: CVE-2023-30533, CVE-2024-22363). Reading `.xlsx` files carries known vulnerability risk until the W04 migration. | File ingestion | Medium | Only accept files from trusted sources | W04 | W04 |
| KL-14 | **The bituminous unit weight disagrees with the source sheet.** The code uses `bituminousUW: 22`; source cell `Factors!B9` indicates 24. One is wrong; the asphalt deviation is unresolved. | Estimation/material take-off | Medium | Do not rely on asphalt tonnage until reconciled | W09 | W09 |
| KL-15 | **No drawing register, and BBS is not reconciled to BOQ.** Drawings are produced as DXF/SVG, but nothing proves the bar-bending schedule equals the bill of quantities, and there is no revision control over figures. | Drawing module | Medium | Cross-check bar schedules by hand | W08 | W08 |
| KL-16 | **Estimation gives totals only.** There are no MoRTH measurement rules and no rate registry bound to the BOQ; the DPR is not yet bound to the estimate. | Estimation | Medium | Treat totals as indicative | W09 | W09 |
| KL-17 | **Report TOC exactness is not verified.** Pagination and table-of-contents page numbers are not asserted anywhere, so a printed report's index may be off. | Deliverables | Low | Check the printed index by hand | W10 | W10 |
| KL-18 | **Accessibility is not claimed.** An a11y gate exists but has not been run to green; WCAG 2.2 AA conformance is not established. | UI | Medium | Do not rely on the UI for accommodation needs yet | W11 | W11 |
| KL-19 | **The T-beam girder family has no full UAT scenario.** `irc-kherka-teegirder` shares the code path but is not exercised by a full acceptance scenario (see `docs/phase-2/UAT-PLAN.md`). | Coverage | Low | Add it to the UAT set in the parity weeks | W02A/W07A | W02A |
| KL-20 | **Gate verdicts in a dirty working tree are provisional.** Escape `E-008` (`GREEN_ONLY_IN_DIRTY_TREE`, `containment/escapes.json`) means a green result recorded while files are uncommitted does not prove the committed tree is green. | Gate harness | Medium | Re-run gates on a clean checkout | standing | CI |
| KL-21 | **No correlation id, alerts or on-call.** Logging is structured, but a request cannot be traced by a correlation id across layers, and there are no alerts or soak evidence. | Observability | Medium | Debug from logs directly | W06/W11 | W11 |
| KL-22 | **CORS can silently deny everything.** When `ALLOWED_ORIGINS` is unset, the origin policy is default-deny; a deployment that forgets to set it will reject legitimate browser origins with no obvious cause. | Deployment | Low | Always set `ALLOWED_ORIGINS` | W04 | W04 |
| KL-23 | **The full gate harness cannot run without a complete install.** The TypeScript gates (`.ts`) need `tsx`; in a worktree without `node_modules` only the plain-`node` `.mjs` gates run. A "gates passed" claim must state which gates ran. | Gate harness | Low | Run `gate:foundation` in CI / a full install | standing | CI |
